# Лабораторная работа №1: запуск DriveNext

Основание: методичка «Разработка мобильных приложений», страницы 50–59,
и требования курса https://lms.mtuci.ru/course/view.php?id=18664.

## Реализовано

- Android 12+ (minSdk 31), Kotlin, XML, MaterialButton, ViewBinding, портретная ориентация.
- AndroidX SplashScreen, тема стартовой Activity, installSplashScreen до super.onCreate.
- Экран загрузки с названием, слоганом и иллюстрацией из макета, 2,5 секунды.
- ConnectivityManager: активная сеть, INTERNET и VALIDATED; отслеживание изменения сети.
- Экран отсутствия интернета с активной кнопкой повторной проверки; возврат к прерванному экрану и слайду.
- Три Fragment в ViewPager2 / FragmentStateAdapter. Свайпы, «Далее», «Пропустить», «Поехали», индикаторы и назад.
- SharedPreferences: прохождение приветствия сохраняется при завершении или пропуске.
- Слои domain, data, presentation. Бизнес-логика вызывается из StartupViewModel.
- Тексты, размеры, цвета и шрифт в ресурсах; учёт системных отступов; прокрутка при малой высоте.
- Иллюстрации извлечены из изображений методички; Montserrat из Google Fonts.

## Граница лабораторной

Авторизация относится к ЛР2, главный экран — к ЛР3. Для перехода после приветствия
предусмотрен экран назначения «Вход / регистрация» без фиктивной авторизации.
UnauthenticatedSessionRepository честно возвращает отсутствие сессии. В ЛР2 его
необходимо заменить реализацией Supabase с проверкой/обновлением access token.
Маршрутизация в HOME при действительной сессии предусмотрена и проверена модульным тестом.
Сетевых запросов к серверу в ЛР1 нет, поэтому загрузчик запросов и серверные ошибки
добавляются вместе с Supabase в следующей работе.

## Самопроверка / сценарий скринкаста

1. Очистить данные приложения для первого запуска (только тестовые данные).
2. Запустить: экран загрузки → первый слайд.
3. Проверить свайпы, «Далее», индикаторы, возврат назад, «Поехали» → экран назначения.
4. Перезапустить: загрузка → экран назначения без приветствия.
5. Снова очистить данные, проверить «Пропустить» и сохранение результата после перезапуска.
6. Отключить сеть: экран «Нет подключения к интернету»; «Повторить попытку» оставляет экран.
7. Включить сеть: возврат на прежний экран; на приветствии сохраняется выбранный слайд.
8. Проверить сворачивание/возврат, маленький экран и увеличенный размер шрифта.

Код и скринкаст можно передать преподавателю до защиты. Баллы выставляются после
личной защиты на паре. Внешняя отправка из этой задачи не выполнялась.

## Сборка

JDK 17+ (на компьютере настроен JDK 21), Android SDK 34, Gradle 8.7.
Для выбранного пути с кириллицей установлен android.overridePathCheck=true.
Проверка: gradlew.bat assembleDebug testDebugUnitTest lintDebug.

Для Windows / JDK 21 в org.gradle.jvmargs используется -Dfile.encoding=COMPAT:
Gradle 8.7 иначе записывает пути к тестовым классам в неверной кодировке.
Описание проблемы инструментария: https://github.com/gradle/gradle/issues/30391.

## Контрольные вопросы ЛР1

1. Переменные Kotlin: val для неизменяемой ссылки, var для изменяемой,
   например val name: String = "DriveNext". Тип часто выводится автоматически.
2. Activity — компонент Android, представляющий окно интерфейса и имеющий
   жизненный цикл. MainActivity размещает интерфейс запуска приложения.
3. Intent описывает действие, например запуск Activity или открытие системного
   приложения. В этой работе страницы меняются внутри одной Activity.
4. SplashScreen обеспечивает непрерывный визуальный переход при старте и скрывает
   короткую инициализацию. Системный экран запуска дополняется макетом загрузки.
5. Тема Theme.DriveNext.Starting указывается в атрибуте android:theme стартовой
   Activity в AndroidManifest.xml; postSplashScreenTheme задаёт следующую тему.
6. installSplashScreen вызывается до super.onCreate и до установки интерфейса,
   чтобы корректно применить тему и привязать стартовый экран к Activity.
7. uses-permission размещается непосредственно внутри manifest, вне application.
   Отсутствие разрешения может привести к отказу операции и SecurityException.
8. INTERNET разрешает сетевые соединения; ACCESS_NETWORK_STATE — чтение состояния
   сети через ConnectivityManager. Это обычные разрешения без диалога запроса.
9. AndroidManifest.xml объявляет компоненты, разрешения, темы и точку входа
   приложения для системы Android.
10. Fragment — переиспользуемая часть интерфейса с собственным жизненным циклом,
    размещаемая в Activity. FragmentStateAdapter создаёт три страницы приветствия;
    Activity владеет окном приложения и общими кнопками навигации.
