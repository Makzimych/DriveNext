# ЛР2 — регистрация и авторизация DriveNext

В работе используется Supabase Auth, Database и Storage. Google OAuth заменён на Яндекс ID по требованию пользователя. В приложение не встроены секрет Яндекс OAuth и service_role. Нужны настройки внешних сервисов; без них приложение показывает ошибку настройки и не имитирует успешный вход.

## Подключение Supabase

1. Создайте бесплатный проект в https://supabase.com/dashboard. Сохраните пароль базы отдельно.
2. В SQL Editor выполните `supabase/lr2.sql` **один раз**: создаются таблица профилей, закрытый бакет фотографий и правила доступа только к своим данным.
3. В Auth → URL Configuration добавьте Redirect URL `drivenext://auth`.
4. В Auth → Providers оставьте Email включённым. Подтверждение почты поддерживается: после регистрации нужно подтвердить письмо и войти, не закрывая приложение. Черновик формы находится в памяти ViewModel и переживает поворот/переходы, но не завершение процесса Android. Для проверки полной регистрации в лабораторной можно отключить Confirm email в тестовом проекте.
5. В настройках проекта найдите Project URL и публичный publishable/anon key. Добавьте в корневой `local.properties` (он исключён из Git):

```properties
supabase.url=https://PROJECT_REF.supabase.co
supabase.key=PUBLIC_PUBLISHABLE_OR_ANON_KEY
```

6. Синхронизируйте Gradle и пересоберите приложение. Эти публичные параметры входят в APK; доступ ограничивают RLS. Секретный `service_role` туда добавлять нельзя.

## Настройка Яндекс ID

Связка: Android → Supabase → Яндекс OAuth → Supabase → Android. Supabase проверяет OAuth state, приложение обменивает код через PKCE. Авторизация проходит в системном браузере, пароли Яндекса приложение не получает.

1. В Supabase Edge Functions создайте и разверните функцию `yandex-userinfo`, используя `supabase/functions/yandex-userinfo/index.ts`. Отключите проверку Supabase JWT для этой функции: входящий Bearer — токен Яндекса. Функция сама проверяет его запросом к Яндексу и возвращает стандартные поля `sub` и `email`. Если используете CLI: `supabase functions deploy yandex-userinfo --project-ref PROJECT_REF --no-verify-jwt`.
2. В Supabase Auth → Providers → New Provider выберите Manual configuration / OAuth2, идентификатор `custom:yandex`. Скопируйте **Callback URL, показанный в форме**.
3. Создайте приложение для авторизации пользователей на https://oauth.yandex.ru/client/new/id/. Название — DriveNext, контактная почта — ваша. Для этой серверной связки выберите платформу веб-сервиса и укажите скопированный Callback URL. Запросите только почту и основные сведения о пользователе (`login:email`, `login:info`).
4. Client ID и Client Secret из Яндекс OAuth внесите **только в настройки провайдера Supabase**.
5. Укажите адреса провайдера:

| Поле | Значение |
|---|---|
| Authorization URL | `https://oauth.yandex.ru/authorize` |
| Token URL | `https://oauth.yandex.ru/token` |
| UserInfo URL | `https://PROJECT_REF.supabase.co/functions/v1/yandex-userinfo` |
| Scopes | `login:email login:info` |
| PKCE | включён |

6. Включите провайдера. Нажмите «Войти с Яндекс ID», разрешите доступ, убедитесь, что браузер возвращает в приложение и открывается пустая Главная.
7. Проверьте отказ в доступе/закрытие браузера, повторный вход и восстановление сессии после перезапуска. Email проверяется на сервере; для OAuth он не ограничивается доменами `.com`/`.ru` формы.

Первый вход через Яндекс создаёт аккаунт Supabase, как OAuth-вход в методичке. Сбор документов относится к отдельной регистрации по почте. Функция намеренно не объявляет почту подтверждённой, чтобы не включать автоматическое объединение аккаунтов по непроверенному атрибуту.

## Реализация и границы

- `domain/AuthModels.kt`: формы, правила валидации и контракт репозитория.
- `data/SupabaseAuthRepository.kt`: запросы к Supabase, загрузка фотографий в закрытое хранилище, профиль, Яндекс OAuth, сессия в Android Keystore/AES-GCM.
- `presentation/AuthViewModel.kt`: переходы, асинхронные операции, защита от двойного запроса, тайм-аут, сохранение черновика при переходах.
- `presentation/AuthFragment.kt`: ViewBinding, MaterialDatePicker, Photo Picker и камера через FileProvider. Отмена выбора сохраняет прежнее фото. Изображения ограничены 20 МБ на входе и уменьшаются до 1600 пикселей.
- Макеты размещены в XML, тексты/размеры — в `values`. Сохранены MVVM, Clean Architecture, портретная ориентация и сценарии ЛР1.
- Дата рождения — `MM/DD/YYYY`, дата выдачи — `DD/MM/YYYY`, согласно тексту методички. Для рождения картинка в методичке противоречит тексту; принят явный текст задания.
- «Далее» на шаге 2 ведёт к документам, затем к завершению, согласно общей последовательности трёх шагов.
- Главная пока пустая — каталог относится к следующей лабораторной.
- Реального сервиса проверки документов нет. Поэтому экран завершения не обещает двухчасовую проверку персональных данных.
- Совместимая группа зависимостей: Kotlin 2.0.21, Supabase SDK 2.5.4, Ktor 2.3.12; изменения проекта не требуют перехода на Compose.
